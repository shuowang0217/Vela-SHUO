# Vela-SHUO Windows 0.1-C 本地可靠性与诊断

本页记录 0.1-C 已实现范围。此阶段仍然是 **UI 原型**，没有真实代理内核，不应把 UI 显示的节点延迟或“已连接”视为实际网络状态。

## 已实现：配置安全

- 主题值仅接受 `dark`、`light`、`system`，无效值恢复安全默认 `dark`，只清理 `vela.shuo.theme.v1` 一项，不清理其他程序或其他配置键。
- 读取失败、非法类型、数据损坏或超时（默认 3 秒）不会阻止首页显示；无法写入则当前 UI 仍可使用。
- 主题写入串行排队，连续切换最终保留最后一次选择。无法取消的底层 I/O 即使超时仍可能在系统恢复后完成，因此并不声称突然断电后的写入具备事务一致性。
- 假存储测试覆盖不合法数据、读取/写入抛异常、超时、快速连续更改和 `system` 模式恢复。

## 已实现：离线本地诊断

- Windows 默认目录：`%LOCALAPPDATA%\Vela-SHUO\Diagnostics\`。
- 日志文件：`events.jsonl` 和最多一份 `events.previous.jsonl`，每文件约 128 KiB 上限；内存最多保存最近 80 条。
- 每行 JSON 仅包含 UTC 时间 `utc` 和固定枚举名称 `event`。**绝不记录**错误字符串、堆栈、网站访问、完整路径、订阅 URL、地址、密钥、配置文件、代理流量或节点信息。
- 事件包括程序启动、前后台状态、Flutter 错误、未捕获错误、设置加载/恢复/读取失败/保存/写入失败。
- 无 `LOCALAPPDATA` 或本地写入失败时退化到仅内存；日志无网络上传或遥测。
- 设置页允许用户查看当前会话事件条数、复制脱敏记录、清除两份本地诊断文件。
- 发生错误时，日志只记录事件类型，**不是可还原堆栈的崩溃报告**。调试构建的 Flutter 控制台错误与正式版日志分离。

## 启动与生命周期

- 应用启动时安装 Flutter 与平台错误钩子，进入前台、后台时登记固定事件。
- 即使偏好存储无响应，启动也有超时兜底；日志写入异步执行，不能因磁盘日志失败阻止 UI 启动。
- 此时尚无代理内核进程，也没有更改系统代理，因此**不存在已实现的代理进程清理或系统代理还原功能**；这些必须在 v0.2 接入真实核心时实现并测试。
- 对于严重框架崩溃，仅记录事件；不保证所有崩溃均可自动恢复。Windows 实机异常退出/电源故障验证仍需进行。
