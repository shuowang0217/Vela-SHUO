# Vela-SHUO v0.3-a SHUO Smart Engine（Windows）

## 已实现的真实能力

在用户成功导入订阅后，「智能优选」页面显示真实节点列表与测试操作。点击「测试下一批」会最多测速 8 个节点；会依次为每个节点生成唯一临时 sing-box JSON（只包含受控本地 mixed 入口、选中远端出口），在临时回环端口启动 **独立** sing-box 子进程，再通过该入口访问 `https://cp.cloudflare.com/generate_204`。只有 HTTPS 握手及预期 204 成功时，才记录实际完整请求耗时（ms），失败则显示「失败」，不伪造 Ping 或 Mbps 数据。测试结束后终止临时进程并删除临时节点配置文件。为了避免高并发导致内核资源消耗，单次操作限制 8 个节点。

使用本次会话的测速样本计算指数移动平均（EMA，旧值 70%、新值 30%），根据最近是否可达、失败次数和连续失败惩罚进行排序。节点名称、地址、密码、原始配置和订阅 URL 不写入评分日志；不保存历史样本到磁盘。

## 稳定性与节点选择

- 推荐候选必须最近检测成功，有评分数据。
- 当前节点健康时，候选的综合得分需同时比当前好至少 **20%**、**50ms**，才允许智能改选。
- 选择后进入 **3 分钟冷却期**，防止连续改变。
- 未测量或检测失败节点不参与最优推荐；未测量节点允许继续分批测试。
- 默认只推荐，不改选。用户打开「空闲时自动选择优选节点」后，测试完成时仅在无连接、无内核活动、无系统代理接管的状态下自动选中更优节点。**绝不会因为测速自动接管 Windows 网络、建立连接，或中断正在工作的 YouTube/其他流量。**
- 不允许当前代理正在运行、系统代理已接管或者正在连接/断开的情况下开启新的批量测速。首要目标是保护已建立连接。
- 节点切换需要正常断开，再在首页主动授权连接；无后台自动热切换。这一限制应在 UI 中明确说明。

## 技术边界和待验收事项

- 测得的是固定 Cloudflare HTTPS 204 请求的响应耗时，**不是 ICMP Ping、游戏下载延迟、下载带宽或任何网站的可达性保证**。
- 独立临时进程会额外占用资源和发起少量外部请求；用户点击按钮才执行。主代理配置、WinINet 系统代理和已运行进程不会被测速程序修改。
- 临时配置含节点连接凭据，放于 Windows 当前用户临时目录，程序在测试退出后尝试删除。操作系统强制结束软件等异常可能留下残留文件，**尚未完成**异常崩溃时的临时文件彻底清理策略。
- v0.3-b1 已加入 **按需 1 MiB 下载样本**，但不代表持续下载带宽；更大体量真实下载带宽、流量统计、故障时自动重连、连接不中断的热切换、节点历史评分持久化和失联告警仍待后续开发。
- 自动测试使用假内核/假网络探针验证逻辑；Windows 实机测速时间、进程清理、DPI/布局、代理恢复仍必须验收。此阶段 **只构建 Windows EXE，不构建 Android APK**。

参见 [v0.2-c 真实连接和系统代理恢复](REAL_CONNECTION_0_2_C.md)。

## v0.3-a2：一键测速全部节点（FlClash 风格）

- 「节点」和「智能优选」两个页面都提供「一键测速全部节点」，点击一次测完整份导入的订阅（解析上限 500 个），无需反复点「下一批」。
- 最多同时运行 **2 个**独立的临时 sing-box 测试任务；每个节点通过 HTTPS 204 探针记录真实请求耗时，测不通显示「失败」，没有完成显示「未测试」。
- 实时显示进度 `已测/总数`、成功数、失败数和进度条；可点击「停止测速」，阻止新的任务开始。已经运行中的最多两个测试会完成超时或清理后结束，不宣称瞬间中断内核。
- 节点列表按实测响应耗时排序（未测节点与失败节点后置）。智能优选页面按每 40 条增量展开，可以查看完整份订阅结果。
- 已连接状态**允许测速**，但临时端口与独立内核不替换/终止当前连接，不修改 Windows 系统代理；连接期间仍禁止自动切换所选节点。
- 整体测试只在用户主动点击时开始，关闭软件、重导入订阅会使未完成的测速结果失效；评分仍只存在本次运行内存中。
- 自动测试增加全节点覆盖、并发不超过 2、停止后不启动待测任务、重复点击不重入、已连接时保持现有系统代理和选择。

注意：本版本测的是 HTTPS 响应时间而非下载带宽、ICMP Ping。所有测速任务发起真实网络请求，节点很多时可能需要数分钟；具体耗时取决于每个节点的自检与超时。需 Windows 实机验证临时进程清理、连接中测速、窗口渲染和系统代理恢复。

## v0.3-b1：按需下载样本与定时健康检查

- 「智能优选」增加「测所选节点下载速度（1 MiB）」。仅使用当前手动选中的节点创建独立的临时 sing-box 进程，经其本地 HTTP 代理请求固定的 `https://speed.cloudflare.com/__down?bytes=1048576`，验证 HTTPS 证书、不跟随重定向、不降级直连、不接受未知大小/编码的响应，严格限制数据量为 1 MiB。仅收到恰好 1 MiB、成功 HTTP 响应时才计算 `Mbps = 字节数 × 8 ÷ 传输耗时（微秒）`；失败时显示失败，绝不展示猜测速度。
- 下载结果在智能优选列表及首页显示，**明确标识「1 MiB 样本」**：它不等于持续带宽、实际下载上限或其他站点速度。大文件测速、上传速度和流量实时统计后续再开发。
- 「智能优选」增加定时健康检查选项：关闭（默认）、每 15/30/60 分钟。只有软件正在运行、无现有测速任务、**当前未连接**且能够安全选择节点时，才运行下一批最多 8 个节点的 HTTPS 延迟检查。不运行下载速度测试。
- 定时器退出软件即取消，设置不保存到磁盘、不做后台服务，不表示即使 Windows 休眠或退出后也会继续运行。已连接时保持当前线路不变，不擅自修改 Windows 代理。
- 测试涵盖临时内核的成功/失败清理、选中节点样本保存与失败提示、连接中下载速度采样不改写系统代理、定时检查默认关闭以及已连接时不发起新测试。

**安全边界：** 测试链接是产品固定可信服务，不允许用户订阅内容替换下载 URL；HTTPS 验证保持系统默认证书策略；下载会消耗订阅流量（每次约 1 MiB 加协议开销），只有用户主动点击才执行。Windows 实机需确认测速端点在实际网络可用，数值与当前节点一致。未进行本机验收前仍为 Beta。

## v0.3-b2：单按钮延迟与速度测量 + FlClash-Custom 策略移植

用户要求避免将延迟测试、下载测试、批次测试和推荐选择分别做成多个常驻按钮，且要求沿用私人仓库 `shuowang0217/FlClash-Custom` 的 `feature/smart-select-v1` 定制策略。因此：

- 智能优选页**只保留一个常驻「一键测速 · 全节点延迟 + 下载速度」**操作；测速期间才显示「停止」。节点页不再提供重复的测速操作入口。
- **单个节点在同一个独立 sing-box 子进程中完成延迟及下载样本**，共享启动与销毁过程；不再重复生成/启动两个临时内核；最多并发 2 个节点，完成后逐个显示真实延迟 ms、实测下载速度 **MB/s** 和失败/未测状态。
- 排行与建议选线按真实下载速度优先，延迟仅作为速度接近时的参考；不同于以前仅按 HTTPS 延迟排序。
- 定制的 AI 模式只测速所选单一国家/地区（HK、JP、SG、TW、US、KR、DE、GB），名称匹配规则沿用用户 FlClash-Custom 的地区标记约束；关闭 AI 后测速整个订阅节点池。
- 智能优选开启时默认 10 分钟检查一次，仅当软件运行且连接空闲才实际启动自动测速；自动检查有单轮约 50 MiB 的限制。大量节点时自动检查不覆盖全部，用户明确点击一键测速才能启动整份订阅的完整测试；超过 50 个节点的手动测速前会提示预计消耗流量（每节点 1 MiB，不包含协议开销）。
- 相比当前节点，**下载速度至少提升 20%** 才允许后续自动优选，设有 3 分钟冷却；AI 首次选择目标国家时绕过 20% 阈值，但需要当前不处于活跃连接状态。
- 用户从「节点」或「设置」页面手动选择节点后自动切换持续暂停，直到明确点击「恢复自动优选」。内部智能选中不误判为手动。
- 页面包含 AI 状态、当前节点、最近实测 MB/s、检测时间、榜单和简要优选历史；其他控制是配置项，不再分裂为多个测速按钮。

**与 FlClash-Custom 的能力差异（必须如实披露）**：FlClash 依赖 Mihomo 的策略组和内核在线切换 API，而 Vela-SHUO 当前用 sing-box 独立节点配置，没有等价的动态代理组切换接口。当前已移植筛选、测速、排序、决策阈值、手动保护与状态交互；**不能宣称已复刻 Mihomo 的原位在线热切换、活跃连接检查或递归代理组选择**。Vela 连接中可测量并显示建议，但不会自动重启本机内核或改变 Windows 系统代理，避免强行断开 YouTube 等业务流量。真正不中断流量的动态切换需后续独立验收。

与 FlClash-Custom 原始 2 MiB 每节点等默认值不同，Vela 现阶段采用**1 MiB 下载样本**，以减少用户点一次全节点测速的流量成本；所测速度仅是短样本估计，不代表持续带宽。
