# Vela v1.4.2 · 双端功能修复预览

基线：已成功构建 Android v1.4.1 与 Windows v1.4.0 的共同代码。
本分支仅用于双端验收，不覆盖任何既有正式 Release。

1. **规则/全局/直连真实生效**：每次切换调用 FlClash/Mihomo 原生 updateConfig；当用户配置完全没有规则时，在加载内存中的副本上补充内网及 CN 直连、MATCH 经 GLOBAL 代理的保守默认规则。已有用户规则原样保留，不把“规则”当作 UI 伪模式。Windows 仍是系统代理，非全流量 TUN；Android 使用系统 VPN。
2. **航线**：世界地图用实际地理经纬度途经点/折线插值，不再使用屏幕级抛物线；太平洋、马六甲/印度洋/苏伊士等按目的地选示意海路。它们是美术示意，不用于真实海航导航。
3. **机场更新**：在系统安全存储的加密 vault 中保存订阅 URL（含令牌的 URL 禁止出现在明文首选项、诊断及日志），重启后仍能更新；不同机场可以分别刷新，并能在连接期间只更新加密存档，不篡改运行中的本地代理或 VPN。
4. **机场编辑**：名称、URL、自动更新开关/间隔、手动刷新、原始 Mihomo YAML 编辑；本地配置转换与验证仍交给原生 Mihomo。
5. **清理测试界面**：删除设置内的“视觉状态预览”模拟连接按钮；保留仅本地的隐私诊断。
6. **双端一致**：两个平台共用新增业务逻辑、世界地图和 Flutter 页面，CI 同时执行 Windows x64 与 Android ARM64；不要只构建其中一端。

注意：已有旧版机场没有被保存过的源 URL，第一次仍需要用户在机场编辑窗口填入原始 HTTPS 订阅地址。自动更新只在应用运行期间按设置间隔触发；连接中的更新会在下次重新启用机场时生效。
