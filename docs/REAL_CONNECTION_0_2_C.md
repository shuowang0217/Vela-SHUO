# Windows v0.2-c · 首页真实一键连接与代理恢复（Beta）

本阶段开始用真实状态驱动首页，不再让「演示连接」冒充已经连接。**不是 TUN/VPN 全局代理**；仅接管遵循 Windows WinINet 手动系统代理设置的应用，例如按系统代理配置工作的主流浏览器。此阶段仍然需要 Windows 实机验收，不作为正式版。

## 连接流程

1. 在「设置 → 订阅导入与节点管理」导入自己的 HTTPS 订阅并选择节点。
2. 在首页看到所选节点名，点击「连接所选真实节点」。程序显示一次明确授权弹窗，说明会替换当前用户的 Windows 手动系统代理设置。
3. 同意后依次确认没有遗留恢复问题、启动选定 sing-box 配置、检测本地 HTTP/mixed 端口、经过本地代理请求 HTTPS 固定检测地址。
4. **只有以上全部通过**才备份 HKCU 下原有 ProxyEnable / ProxyServer，把 Windows 用户代理设为 `127.0.0.1:20808` 并通知 WinINet 刷新。
5. 首页最终「已连接（系统代理）」表示本次远端验证成功且已确认当前 Windows 手动代理由本程序接管；不代表所有 App、网站都可达。节点实际 IP 未做可信地理定位。
6. 首页「安全断开并恢复代理」优先恢复原有 ProxyEnable / ProxyServer，复核恢复后才关闭内核。

如果原先存在 PAC（AutoConfigURL）脚本，当前版本拒绝接管，不覆盖 PAC。本阶段暂不修改自动发现设置、Windows WinHTTP、TUN/VPN、DNS、其他系统权限或第三方代理软件配置。

## 故障/冲突与恢复

- 启用系统代理前，在 `%LOCALAPPDATA%\Vela-SHUO\State\proxy-recovery.json` 写入本次会话原设置快照，写入落盘后才尝试更改 HKCU。
- 断开时仅当当前代理值仍与本程序设置匹配才恢复。如果用户/其他代理软件中途修改，避免覆盖其后续配置。
- 如果恢复失败，**不会主动杀掉仍被 Windows 系统代理引用的本机内核进程**，而是提示用户检查系统代理配置。
- 程序启动时优先检查恢复快照，如果当前设置仍属于本程序则尝试恢复；如检测到其他程序已经接管，则保留其新设置。
- 正常退出会请求异步恢复。任务管理器强杀、异常断电时，无法保证立即恢复，必须在下一次 Vela-SHUO 启动时检查；如果无法恢复，需要手动检查 Windows 设置 → 网络和 Internet → 代理。**不得宣称已实现强杀后立即自动恢复**。
- 连接状态异常或内核退出时尝试恢复系统代理；异常期间可仍短暂影响当前应用访问。
- 系统代理仍可能受 Windows 同时运行的其他程序、AutoDetect 和浏览器独立代理设置影响；实机应验证不同软件行为。
- 真实节点名称可推测球体国家视觉方向，**不是精确定位**；不支持判断地理位置时地球留在中国视角。

## 测试覆盖和待完成

单元测试验证正常备份/恢复、崩溃后下次启动恢复、PAC 阻断、第三方代理冲突、恢复失败不删日记、远端 HTTPS 检测失败不得接管 Windows，以及内核意外退出触发恢复。真实延迟、吞吐、自动切换及网络中断后的自动重连尚未完成。

Windows 正式版仍需要：Windows 11 实机 100/125/150% DPI、WinINet 刷新、原代理恢复、真实浏览器访问、断电与强杀、休眠唤醒、订阅身份安全存储及内核进程残留检查。Android 继续暂停到 Windows 正式版验收完成后。
