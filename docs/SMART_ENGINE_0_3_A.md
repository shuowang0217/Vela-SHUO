# Vela-SHUO v0.3-a SHUO Smart Engine（Windows）

## 已实现的真实能力

在用户成功导入订阅后，「智能优选」页面显示真实节点列表与测试操作。点击「测试下一批」会最多测速 8 个节点；会依次为每个节点生成唯一临时 sing-box JSON（只包含受控本地 mixed 入口、选中远端出口），在临时回环端口启动 **独立** sing-box 子进程，再通过该入口访问 `https://cp.cloudflare.com/generate_204`。只有 HTTPS 握手及预期 204 成功时，才记录实际完整请求耗时（ms），失败则显示「失败」，不伪造 Ping 或 Mbps 数据。测试结束后终止临时进程并删除临时节点配置文件。为了避免高并发导致内核资源消耗，单次操作限制 8 个节点。

使用本次会话的测速样本计算指数移动平均（EMA，旧值 70%、新值 30%），根据最近是否可达、失败次数和连续失败惩罚进行排序。节点名称、地址、密码、原始配置和订阅 URL 不写入评分日志；不保存历史样本到磁盘。

## 稳定性与节点选择

- 推荐候选必须最近检测成功，有评分数据。
- 当前节点健康时，候选的综合得分需同时比当前好至少 **20%**、**50ms**，才允许智能改选。
- 选择后进入 **3 分钟冷却期**，防止连续改变。
- 未测量或检测失败节点不参与最优推荐；未测量节点允许继续分批测试。
- 默认只推荐，不改选。用户打开「空闲时自动选择优选节点」后，测试完成时仅在无连接、无内核活动、无系统代理接管的状态下自动选中更优节点。**绝不会因为测速自动接管 Windows 网络、建立连接，或中断正在工作的 YouTube/其他流量。**
- 不允许当前代理正在运行、系统代理已接管或者正在连接/断开的情况下开启新的批量测速。首要目标是保护已建立连接。
- 节点切换需要正常断开，再在首页主动授权连接；无后台自动热切换。这一限制应在 UI 中明确说明。

## 技术边界和待验收事项

- 测得的是固定 Cloudflare HTTPS 204 请求的响应耗时，**不是 ICMP Ping、游戏下载延迟、下载带宽或任何网站的可达性保证**。
- 独立临时进程会额外占用资源和发起少量外部请求；用户点击按钮才执行。主代理配置、WinINet 系统代理和已运行进程不会被测速程序修改。
- 临时配置含节点连接凭据，放于 Windows 当前用户临时目录，程序在测试退出后尝试删除。操作系统强制结束软件等异常可能留下残留文件，**尚未完成**异常崩溃时的临时文件彻底清理策略。
- 真实下载带宽、流量统计、故障时自动重连、连接不中断的热切换、节点历史评分持久化、失联告警等需要后续 v0.3-b 开发。
- 自动测试使用假内核/假网络探针验证逻辑；Windows 实机测速时间、进程清理、DPI/布局、代理恢复仍必须验收。此阶段 **只构建 Windows EXE，不构建 Android APK**。

参见 [v0.2-c 真实连接和系统代理恢复](REAL_CONNECTION_0_2_C.md)。

## v0.3-a2：一键测速全部节点（FlClash 风格）

- 「节点」和「智能优选」两个页面都提供「一键测速全部节点」，点击一次测完整份导入的订阅（解析上限 500 个），无需反复点「下一批」。
- 最多同时运行 **2 个**独立的临时 sing-box 测试任务；每个节点通过 HTTPS 204 探针记录真实请求耗时，测不通显示「失败」，没有完成显示「未测试」。
- 实时显示进度 `已测/总数`、成功数、失败数和进度条；可点击「停止测速」，阻止新的任务开始。已经运行中的最多两个测试会完成超时或清理后结束，不宣称瞬间中断内核。
- 节点列表按实测响应耗时排序（未测节点与失败节点后置）。智能优选页面按每 40 条增量展开，可以查看完整份订阅结果。
- 已连接状态**允许测速**，但临时端口与独立内核不替换/终止当前连接，不修改 Windows 系统代理；连接期间仍禁止自动切换所选节点。
- 整体测试只在用户主动点击时开始，关闭软件、重导入订阅会使未完成的测速结果失效；评分仍只存在本次运行内存中。
- 自动测试增加全节点覆盖、并发不超过 2、停止后不启动待测任务、重复点击不重入、已连接时保持现有系统代理和选择。

注意：本版本测的是 HTTPS 响应时间而非下载带宽、ICMP Ping。所有测速任务发起真实网络请求，节点很多时可能需要数分钟；具体耗时取决于每个节点的自检与超时。需 Windows 实机验证临时进程清理、连接中测速、窗口渲染和系统代理恢复。
