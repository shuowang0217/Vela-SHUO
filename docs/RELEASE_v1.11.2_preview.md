# Vela v1.11.2-beta.2+66 网络稳定性测试版

基于 v1.11.1+64；本版本仅提供 Windows x64 / Android ARM64 测试构建，不是正式 GitHub Release。

- 自动路由：连接时每 15 秒在本地通过 Mihomo getProxies 查询 URLTest/Fallback 的当前选择成员。只有选择链变化时才重新查出口 IP，正常仍每 2 分钟检查公网 IP。
- 网络恢复：离开前台超过 45 秒返回才进行路由及出口复检，短时间切窗口不重复检测；超过 6 分钟的缓存立即失效。不会自动打开 VPN 或系统代理。
- 分层诊断：设置页手动检查系统 DNS 与经过 Mihomo 的 HTTPS 两条链路，显示独立状态。系统 DNS 不等于代理 DNS。
- 界面不变：继续保留油画国旗、航海地图、连接状态及 Android VPN。
- 版本：1.11.2-beta.2+66，Android 包名 com.shuowang.vela，使用原长期签名；不覆盖正式 Release v1.11.0。

说明：自动分组选择仅代表当前组的链路，不等于规则模式对所有目标域名的路由。DNS 使用系统解析，不能证明 Mihomo 内置 DNS 的最终结果。


## beta.2+66 测速加速

- Native batch URLTest：在原始 1 MiB 下载检测以外，提高批量延迟任务的最大并发到 20；首次 URLTest 2.4 秒，第二检测源 1.6 秒，失败节点不再占用过长队列。
- 单节点延迟检测：仍采用 FlClash Go 原生 URLTest + probe，缩短 HTTPS 超时，不制造本地模拟延迟。
- 下载测速：独立下载全节点扫测与综合扫描最多同时执行 2 个真实下载；单节点手动测试依旧 1 个；保留 1 MiB 完整 HTTPS 采样和最小 256 KiB 有效响应校验。每个 CDN 上限缩短为 6.5 秒，保留备选 CDN。
- UI 继续分别展示延迟与下载结果；下载 CDN 失败不抹掉成功的延迟；取消扫描不再安排新任务。
- **注意**：并发下载会分享用户当前连接带宽，因此每个节点显示的 Mbps 是采样值，不等于独占线路峰值。真实速度随网络环境变化。
- 版本更新为 1.11.2-beta.2+66，仍不发布正式版。
