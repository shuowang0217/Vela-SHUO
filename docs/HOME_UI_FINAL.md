# Vela-SHUO 首页 UI 定稿规范（Windows 优先）

> 状态：**视觉与交互方向已由产品方确认**。定稿日期：2026-10-09。
> 本文为后续 Windows EXE 开发与最终 Android 适配的共同设计基准；不代表代理功能或正式版验收完成。

## 1. 品牌与文案（不可自行替换）

- 产品：**VELA** / **— SHUO —**。在设置、窗口标题、文件名中使用 **Vela-SHUO**。
- 唯一首页品牌标语：**一帆越洋，尽览四方。**
- 首页头图区仅包含以上产品名与中文标语。
- 删除「更自由的连接世界」「INTELLIGENT CONNECTIVITY」「智能路由，畅行全球」「让重要的连接，更简单」等旧文案。
- 品牌文案与产品功能信息应分离：连接卡片继续明确写明「UI 演示」「尚未接入代理」，不能把演示动画暗示成真实连网成功。
- 面向用户的操作/设置语言仍为中文；**地球表面的地理标签**统一使用简洁英文城市名。

## 2. 品牌排版与色彩

| 用途 | 规范 |
| --- | --- |
| VELA 主字 | Segoe UI，Bold，59px，字符间距 5，颜色 `#F2F8FF`（桌面设计坐标） |
| SHUO 副字 | Segoe UI，28px，字符间距 5，冰蓝 `#80C7F8` |
| 中文标语 | 17px、常规字重、字距 1.6、行高 1.5，`#B1C6DC` |
| 窄屏品牌标语 | 10px、字距 .5，位于产品名称下方 |
| 海洋背景 | `#06111F`、`#0B2038` 渐变 |
| 玻璃卡片 | `#0B1E33` 半透明，边线 `#2A4863`，圆角 18px |
| 连接强调 | `#80C7F8` 冰蓝；成功强调 `#63E6B7` 薄荷绿 |
| 地图标签 | Segoe UI（Arial 回退），全大写，半粗体，字符间距 .85 |

产品名称和标语以充分留白表现，不再添加技术宣传或长篇功能解释。Windows 系统缺少字体时遵从 Flutter 字体回退。

## 3. 首页构图与布局

- Windows 桌面宽度 >= 820 采用左侧导航 + 主画布； >= 1250 的侧栏展开品牌文字与导航名称。
- 主画布采用约 760px 高的参考设计空间，通过 `FittedBox(BoxFit.contain)` **整体适配可用窗口**，保证连接卡片、统计卡与地球不会因为固定最小高度而被窗口裁剪。
- 大地球位于画面右侧；品牌名与标语在左上部，连接卡位于左侧中下部；底部横向为网络延迟、下载、智能模式、连接时长四个统计卡。
- 窄屏布局采用纵向滚动：品牌/标语、地球、连接卡、两行指标卡。Android 仍然冻结发布。
- 保留现有冷海蓝玻璃材质、发光氛围、简笔帆船与柔和卫星地球纹理，不重做已认可的地图视觉。

## 4. 地球与航行交互（行为契约）

| 状态/事件 | 地球与帆船行为 |
| --- | --- |
| 初始未连接 | 地球朝向中国大陆，以北京附近作为出发点 |
| 连接开始 | 地球朝选定目的地平滑转动，帆船沿**清楚可见的二次贝塞尔弧线**航行 |
| 演示状态先于航行结束 | 连接卡文字允许先改变，但**不得强制帆船瞬移到终点，也不得重启正在运行的动画 ticker** |
| 到达目标 | 船只自然减速停靠，目的地英文标签显示 |
| 主动断开 | 先沿原航线将帆船**从当前进度反向航回出发点**，再让地球自然转回中国视角 |
| 返航中再次连接同一节点 | 在当前帆船位置接续前航，不发生航线进度跳变 |
| 改选目的地 | 从当前地球朝向平滑转向新节点，不瞬间回原点 |
| 云层 | 半透明轻薄云带，在球体范围内缓慢漂移，95 秒循环，始终处于地表上方、航线下方 |
| 地图地点 | 出发点 **BEIJING**，目标依次使用 **TOKYO / SINGAPORE / LOS ANGELES / LONDON / FRANKFURT** |

当前演示版的地球转动时长为约 1650ms，帆船单程时长约 1550ms；两者允许独立进度，以流畅和连续为优先。连接状态演示计时不等于网络连接耗时。

## 5. 动效性能与兼容性验收

- 首先在 Windows 64 位开发/测试机器上确认 100%、125%、150% 显示缩放下默认窗口没有裁剪关键操作区。
- 实机观察前进 0–100%、反向航回及中途取消/重连：无突然位置跳跃，无未结束时船只消失。
- 地图渲染不应因云层独立动画造成明显持续卡顿；60fps 为后续优化目标，**未进行实机帧率验收前不得称已达标**。
- 自动化测试覆盖文案、不同宽度构图、航线曲率、连接阶段与返航阶段动画进度；Windows Release 编译与便携 ZIP 附带 DLL/data 校验必须通过。
- 所有状态模拟必须标识为演示数据，不标注虚假的真实延迟/下载速度。

## 6. 正式功能开发边界及先后顺序

本规范只冻结 **主界面视觉/动效设计**，不冻结网络核心能力的开发。下一阶段按以下里程碑执行：

1. **Windows 0.1-C — 基础可靠性：**脱敏日志、启动/异常恢复、配置数据校验、本地诊断、离线正常启动；完善自动化验收。
2. **Windows 0.2 — 可用的真实连接：**完成核心许可与安全审查、独立代理内核适配、配置/订阅导入校验、节点选择、启动/关闭/错误处理、进程退出清理、系统代理的显式启停与还原，标识真实连接状态，保护用户网络设置。
3. **Windows 0.3 — 智能优选：**真实延迟/吞吐测速、周期评分、滞后门限与冷却时间、避免抖动切换、异常恢复与切换日志。
4. **Windows 正式版：**跨 DPI/窗口尺寸验收、干净卸载与异常恢复、更新/版本发布验证，完成 EXE/便携分发。
5. **Android：**仅在 Windows 正式版经过用户验收后启动 VPN 服务、权限与生命周期适配，再做签名 APK 与真机测试。

**不做：**将现有 UI 演示逻辑冒充代理连接；复用旧 FlClash-Custom 源码；未获授权自动更改用户系统代理；当前阶段构建 Android APK。

相关实现：`lib/src/app.dart`、`lib/src/home/globe.dart`、`lib/src/home/demo_connection.dart`。总体计划见 [ROADMAP.md](ROADMAP.md)。
